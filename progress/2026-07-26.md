### Follow-up — native tab bar icons and Liquid Glass

User noticed every tab showed a downward-arrow icon and asked whether Expo supports native Liquid Glass. Root cause: Task 9 never set a `tabBarIcon`, so `expo-router`'s JS `Tabs` (React Navigation under the hood) fell back to its built-in `MissingIcon` placeholder glyph (`⏷`). Traced this into the vendored `node_modules/expo-router/build/react-navigation/elements/MissingIcon.js` before proposing fixes.

Presented the user three options for how far to take it (icons-only fix on the existing JS `Tabs`; keep JS `Tabs` but drop `GlassSurface` in as `tabBarBackground`; or swap to `expo-router`'s `NativeTabs`, a real `UITabBarController`-backed tab bar that gets iOS 26's system Liquid Glass automatically). User chose the full native-tabs swap with icons sourced from `@expo/vector-icons` rather than raw SF Symbol strings.

Delegated to [Implement native Liquid Glass tab bar](f8fa42de-0586-41ce-a8a9-b1a16c1b2a36) on Cursor Grok 4.5 (high): replaced `Tabs` with `NativeTabs` in `app/(tabs)/_layout.tsx`, wired Ionicons (outline when unselected, filled when selected) through `NativeTabs.Trigger.VectorIcon`, left `backgroundColor` unset so the native bar's automatic Liquid Glass rendering isn't overridden, and updated `tabShell.test.tsx`'s `expo-router/unstable-native-tabs` mock accordingly. Added `@expo/vector-icons` and the `expo-font` peer/plugin. Verified independently: re-read the diff, re-ran `npx tsc --noEmit` (clean) and `npx jest` (69/69) myself rather than trusting the subagent's report alone.

Committed as `2179b70` — "feat: use NativeTabs with vector tab icons". Note for later: `NativeTabs` ships in Expo Go for SDK 57, so no dev-client rebuild is needed to try it, but actually seeing the glass material depends on the Expo Go binary being linked against the iOS 26 SDK — not something to debug in this codebase if it looks flat on an older Expo Go build.
